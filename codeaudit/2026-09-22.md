# WinOnLinux code audit — 2026-09-22

Audit of `src/winonlinux/` (16 modules, 4,318 lines) per `0_codeaudit.txt`: security (Part A), resiliency (Part B),
Ubuntu-desktop look-and-feel foundation (Part C), tests and verification debt (Part D). Normative baseline: `spec.md`
§4, §5.7, §6, §9, §10, §14. Scope honoured: only the three applied changes (`add-app-foundation`,
`add-auth-account-manager`, `add-cloudpc-enumeration`) are audited; missing features belonging to unapplied changes
are not findings.

**Suite execution:** run locally during this audit on Python 3.12 (venv, no PyGObject): **171 passed, 1 failed** in
1.98 s. The failure is finding F-09. CI exists (`.github/workflows/ci.yml`) and pins Python 3.11.

---

## 1. Executive summary

The applied code is in materially better shape than most early-stage auth-handling desktop code: the token cache is
genuinely keyring-only with no reintroduced fallback, every MSAL mutation path sits inside both the single-flight
lock and the cache-write serializer, the loopback listener is bind-correct/single-response/deadline-sound with no
reflected content, redaction is enforced structurally at the LogRecord factory, state writes are atomic with fsync
and an effective 0600 mode, and no `shell=True` or `verify=False` exists anywhere. Two of the audit prompt's own
premises proved wrong in the code's favour (state-file mode and fsync — see §5). The one HIGH finding is a real
token-exfiltration gap: `@odata.nextLink` is a remote-supplied URL fetched with a fresh bearer token attached and no
scheme/host validation. The MEDIUM tier clusters into three themes: malformed-remote-data and cross-account blast
radius in the enumeration path; lifecycle gaps (sign-out leaves the poll loop running; shutdown cancels but never
awaits); and missing change-notification plumbing that the unapplied UI shell will need and that is expensive to
retrofit. One MEDIUM was found only by executing the suite: it fails on Python 3.12 due to a module-level
`asyncio.Lock` binding to the first contended event loop.

**Counts:** CRITICAL 0 · HIGH 1 · MEDIUM 9 · LOW 12 · INFO 4.

## 3. Per-finding detail

### F-01 · HIGH · `@odata.nextLink` token exfiltration (A5)

`refresh_now` loops `url = page.get("@odata.nextLink")` (`cloudpc_provider.py:255`) and passes it straight back into
`graph_get_json`, which acquires a **fresh access token** and sends `Authorization: Bearer <token>` to whatever URL
that is (`graph_client.py:200-205`). Nothing checks scheme or host — verified independently twice and re-confirmed
directly: no `urlsplit`/`urlparse`/host check exists in either module. Failure scenario: any party able to influence
a Graph response body (TLS-inspecting middlebox with a trusted CA — the population §10.8 explicitly accepts as
present; or a future response-injection bug) supplies `"@odata.nextLink": "https://attacker.example/x"` and receives
a live Graph access token. A non-string value also flows unchecked into `requests.get` (type confusion). Spec ref:
§10.1's host-allowlist principle; D-4 (no pinning) makes middlebox presence a designed-for condition, which is
exactly why the URL itself must be validated. **Remediation:** in `graph_get_json` (single choke point), before
sending: require `isinstance(url, str)`, parse with `urlsplit`, require scheme `https` and host
`graph.microsoft.com` (exact), raise `GraphError` otherwise. **Pinning test:** nextLink to `https://evil.example/` →
assert no second HTTP call and no token acquired for it; assert `http://graph.microsoft.com` also rejected.

### F-02 · MEDIUM · Redaction destroys every GUID (A6)

`_OPAQUE_TOKEN_PATTERN = re.compile(r"\b[A-Za-z0-9_-]{32,}\b")` (`logging_setup.py:105`) — hyphen inside the class,
so a 36-char hyphenated GUID matches. Empirically confirmed: `"cloudpc id 550e8400-…-446655440000"` →
`"cloudpc id [REDACTED]"`; a `home_account_id` (`oid.tid`) renders `[REDACTED].[REDACTED]`. Every per-account log
line (e.g. `auth_manager.py:379`) becomes uncorrelatable, blinding exactly the multi-account diagnosis §9's
per-account error rows require. The audit prompt's bar — "Cloud PC GUIDs must survive; real tokens must not" —
fails on the first half. Over-redaction is the safe direction, hence MEDIUM. `state_store.py:74` already has the
UUID carve-out this needs. **Remediation:** exclude canonical 8-4-4-4-12 UUIDs (and dotted pairs) before the
opaque-token sub, mirroring `state_store`. **Pinning test:** bare GUID and `oid.tid` survive; 40-char undashed
base64url run is redacted.

### F-03 · MEDIUM · Malformed Graph data escapes the typed taxonomy (B3)

`_entry_from_raw` does `raw["id"]` (`cloudpc_provider.py:106`); `refresh_now`'s except clauses catch only the
`GraphError` family (`:246-277`); `graph_get_json` calls `response.json()` outside its try (`graph_client.py:227`).
A 200 page with one entry missing `id`, a non-list `value`, or a malformed-JSON 200 body escapes as an untyped
`KeyError`/`JSONDecodeError`: a direct caller (the future manual-refresh UI) crashes instead of receiving `Failed`;
in the poll loop it is swallowed by the broad `except Exception` (`:390`) as a generic warning. Spec §9's "beta
contract change" row wants a typed, presentable outcome. **Remediation:** wrap non-`GraphError` parse exceptions
into `Failed` (or a dedicated `ContractChanged` result); catch `ValueError` from `.json()` on 200 and raise
`GraphError`. **Pinning tests:** page with an entry missing `id` → `Failed`, not `KeyError`; 200 non-JSON body →
`GraphError`.

### F-04 · MEDIUM · Cross-account bleed through `last_result` (B3)

`last_result` is a single account-agnostic attribute (`cloudpc_provider.py:208`); `Failed` carries
`previous = self.last_result.entries` (`:269`). Account A enumerates; user switches to B (`app.py:298-318` starts
B's refresh; nothing resets provider state); B's first refresh fails → `Failed(previous_entries=A's Cloud PCs)` is
presented as B's previous results, and `last_result` still holds A's `Enumerated` for any reader until B's first
success. Violates FR-3 per-account isolation. The existing test
(`test_failed_refresh_keeps_previous_entries`) never switches accounts. **Remediation:** key `last_result` by
`home_account_id`, or clear it when `refresh_now` runs for a different account. **Pinning test:** refresh A
(Enumerated) → refresh B raising `GraphNetworkError` → `Failed.previous_entries == []`.

### F-05 · MEDIUM · `sign_out` leaves the poll loop running forever (B1/B3)

`sign_out` (`auth_manager.py:405-433`) removes the account from `self.accounts` and reassigns the active account but
never calls `task_registry.cancel_group`/`destroy_group`, and no caller stops polling. The orphaned poll task ticks
every 60 s: `acquire_token_silently` hits `self.accounts[home_account_id]` (`:496`) → bare `KeyError` (not an
`AuthError`) → caught by the poll loop's broad handler (`cloudpc_provider.py:386-396`) → logged → repeats
indefinitely. `last_result` continues holding the signed-out account's entries (compounds F-04). Violates
FR-3-AC-3 and the purpose D-18 gives task groups. **Remediation:** `sign_out` destroys the account's task group (or
the app layer stops polling on sign-out); make `acquire_token_silently` raise a typed `AuthError` for an unknown
account. **Pinning test:** start polling, sign the account out → poll task cancelled;
`acquire_token_silently(unknown)` raises an `AuthError` subclass.

### F-06 · MEDIUM · Shutdown cancels but never awaits (B4)

`do_shutdown` (`app.py:348-355`) calls `destroy_group` (which `task.cancel()`s) then immediately
`asyncio_bridge.uninstall()`, which closes the loop with no final pump (`asyncio_bridge.py:141-154`).
`CancelledError` is never delivered, so no coroutine's `except`/`finally` runs (asyncio emits "Task was destroyed
but it is pending"), and the default executor is never drained: an in-flight `run_blocking(requests.get, …)`
non-daemon thread blocks interpreter exit for up to the 30 s request timeout — user quits, process lingers. Today's
coroutines carry no critical `finally` blocks, so current impact is exit lag and warning noise; this bites harder
once launcher/session tasks exist. **Remediation:** after cancelling, pump the loop bounded until tasks settle, then
uninstall; bound-join the executor. **Pinning test:** task with a `finally` flag; simulate the shutdown sequence →
flag set before loop close.

### F-07 · MEDIUM · Poll outcomes unobservable — no provider listener (C2)

`_poll_loop` discards `refresh_now`'s return value; a `Failed` never updates `last_result` (by design) and reaches
no one (`cloudpc_provider.py:371-397`). Network drops at t=0 → every tick fails → no callback, signal, or attribute
records that refreshes are failing. The future UI cannot raise §4.4's Offline banner or Error state or update §4.3's
status chips without running its own duplicate timer over `last_result`. The observer pattern already exists in this
codebase (`AuthManager.add_active_account_listener`, `auth_manager.py:269`) — the provider just lacks it, and it is
exactly the retrofit-expensive foundation gap Part C targets. **Remediation:**
`add_result_listener(Callable[[str, EnumerationResult], None])` invoked on every refresh outcome including `Failed`.
**Pinning test:** poll tick raising `GraphError` invokes the listener with `Failed` carrying `previous_entries`.

### F-08 · MEDIUM · No auth-state-change signal for the ReauthRequired banner (C2)

A background silent acquisition hitting `invalid_grant` moves the account ACTIVE → REAUTH_REQUIRED
(`auth_state.py:202-206`); the error is swallowed by the poll loop and nothing notifies anyone. §4.4 requires a
per-account non-blocking banner *when* this happens; the only listener `AuthManager` offers is for active-account
identity changes (`auth_manager.py:267-286`). Same gap covers surfacing DEVICE_CA_BLOCKED and OFFLINE.
**Remediation:** `add_auth_state_listener(Callable[[str, AuthState], None])` fired from
`apply_error`/`mark_active`/`mark_offline`/`sign_out`. **Pinning test:** INVALID_GRANT-classified `apply_error`
fires `(home_account_id, REAUTH_REQUIRED)`; DEVICE_CA_BLOCKED fires exactly once.

### F-09 · MEDIUM · Suite fails on Python 3.12 — singleton lock binds to first contended loop (D)

Run during this audit (Python 3.12 venv): `171 passed, 1 failed` —
`test_sign_out_concurrent_with_in_flight_acquire_does_not_raise_keyerror` fails with
`RuntimeError: <asyncio.locks.Lock …> is bound to a different event loop`; it passes in isolation. Root cause:
`cache_write_serializer` is a module-level singleton (`auth_cache.py:257`) whose `asyncio.Lock` (`:246`) binds to
the first event loop that **contends** it (uncontended acquires skip `_get_loop()`); each test runs in a fresh loop,
so a later contended use in a new loop raises. Production is safe today only because the app runs exactly one loop
per process — an assumption nowhere pinned. `pyproject.toml` says `requires-python = ">=3.11"` unbounded;
`.github/workflows/ci.yml` tests 3.11 only, so CI cannot see this. **Remediation:** create the serializer per
`AuthManager` lifetime (or lazily per running loop), and/or add 3.12/3.13 to the CI matrix; at minimum reset the
singleton in a test fixture. **Pinning test:** the existing failing test, run in a full-suite order on 3.12.

### F-10 · MEDIUM · Loopback size/stall limits are docstring-asserted, untested (A3/D)

The 16 KiB cap is `limit=_MAX_REQUEST_BYTES` on `start_server` plus a 10 s `wait_for(reader.readline())`
(`auth_loopback.py:53,154,308`) — mechanism verified by reading; behaviour for an oversized request line
(`LimitOverrunError` → invalid-response path `:255-257`) and for a stalled connection concurrent with the real
redirect is exercised by no test. Ground rule 3: a control asserted in a docstring but not pinned in a test is a
finding. **Remediation:** two tests — a >16 KiB request line → 400 and the deadline/other connections unaffected; a
stalled connection → freed at 10 s without consuming the accept slot.

### F-11 · LOW · Anchored secret patterns miss embedded tokens (A6)

`_JWT_LIKE_PATTERN` and `_OPAQUE_TOKEN_LIKE_PATTERN` are `^...$`-anchored and matched whole-value
(`state_store.py:59,66,127-131`). Empirically confirmed: `save({"data": "note: eyJ…header.payload.sig"})` persists
the JWT. The realistic accident this defence-in-depth control exists for is a caller concatenating a token into a
diagnostic string — precisely the case it misses. **Remediation:** additionally `search` unanchored variants inside
string values, mirroring `logging_setup`'s unanchored forms. **Pinning test:** token embedded mid-string under an
innocuous key → `SecretValueRejected`.

### F-12 · LOW · Dependency floors admit CVE'd `requests`; no lock strategy (A7)

`requests>=2.27.0` (`pyproject.toml`) admits versions carrying CVE-2023-32681 (Proxy-Authorization forwarded
cross-host), CVE-2024-35195, and CVE-2024-47081 (`.netrc` credential leak via `trust_env`) — the last on exactly the
`trust_env=True` proxy path this app depends on (§5.9). `pygobject` and `pytest` are wholly unpinned; no
lock/constraints file exists. Applicability of each CVE to this call pattern is ASSUMED (no netrc/proxy-auth
configured here). **Remediation (recommend, per ground rules):** floor `requests>=2.32.4`; add a
`pip-compile`-generated constraints file the future Flatpak manifest consumes as its pinned module list; CI
`pip-audit`.

### F-13 · LOW · Unstarted manager fails closed but untyped (A1/B4)

After `start()` raises `KeyringUnavailable`, `self._app` stays `None` (`auth_manager.py:247`) and nothing guards it:
`add_account()` opens the loopback listener socket (`:641-643`) **before** first touching `self._app` (`:652`) and
then dies with `AttributeError`; `acquire_token_silently` for a removed/unknown account raises bare `KeyError`
(`:496`). No token is ever mishandled — D-2 holds — but the D-2 refusal state ("plain explanation, sign-in
disabled") is unenforceable at this layer. (Also reported independently by Part B; merged.) **Remediation:** raise a
dedicated `AuthManagerNotStarted(AuthError)` (or re-raise `KeyringUnavailable`) at the top of the public methods,
before any socket opens. **Pinning test:** unstarted manager → `add_account()` raises the typed error and no
`LoopbackListener.start` occurs.

### F-14 · LOW · DEVICE_CA_BLOCKED terminality guarded on only two of five mutators (A4)

`apply_error` (`auth_state.py:199-200`) and `begin_interactive` (`:163-167`) guard the terminal state;
`mark_active`, `mark_offline`, `begin_silent_refresh` assign `self._state` unconditionally (`:171-189,208-212`).
Unreachable today — `auth_manager.py:503-504,571-572` short-circuit blocked accounts first (verified) — but a future
caller (e.g. `add-cloudpc-actions` catching a network error and calling `mark_offline`) would silently resurrect a
blocked account, violating §6.5's "no category escapes except `sign_out()`". **Remediation:** same guard in the
three unguarded mutators. **Pinning test:** drive to DEVICE_CA_BLOCKED, call each mutator, assert state unchanged.

### F-15 · LOW · `app.py` direct execution bypasses redaction (A6)

Only `winonlinux/__main__.py:28` calls `configure_logging()`; `app.py:372-373`'s own
`if __name__ == "__main__": sys.exit(main())` starts the full app with no record factory and no filter — every log
line (including msal/urllib3 DEBUG if the level is raised) is unredacted. §10.7's "enforced structurally" holds on
one of two entry paths. **Remediation:** delete `app.py`'s `__main__` block, or have `app.main()` call
`configure_logging()` (already idempotent). **Pinning test:** `app.main` installs the record factory before `run()`.

### F-16 · LOW · 5xx never retried (B2)

`graph_client.py:276-280` surfaces 502/503/504 immediately as generic `GraphError` while 429 gets up to 5 retries.
§9 mandates retry only for 429, and the behaviour is pinned by `tests/test_graph_client.py:157`, so this is
hardening, not a violation. **Remediation:** retry 502/503/504 within the same backoff budget.

### F-17 · LOW · Honoured `Retry-After` uncapped (B2)

`sleep_seconds = retry_after` with no cap (`graph_client.py:244-247`); the backoff path caps at 30 s, the header
path doesn't. `Retry-After: 3600` sleeps an hour per attempt — the poll tick appears hung for potentially hours of
retry budget. **Remediation:** cap the honoured value (e.g. 300 s) or surface `GraphThrottled` immediately above a
threshold, carrying the existing `retry_after_seconds` field. **Pinning test:** 429 with `Retry-After: 3600` →
sleep capped.

### F-18 · LOW · Silent-refresh offline path: no backoff, AT retention delegated to MSAL (B1)

§6.4: "network failure during SilentRefresh → retry with backoff; keep using an unexpired cached AT; else Offline."
The code does no backoff — first network exception → `mark_offline()` + `OfflineNoCachedTokenError`
(`auth_manager.py:521-536`). OFFLINE-not-REAUTH_REQUIRED is correct and tested; whether a still-valid cached AT
would have been served rests entirely on MSAL returning cached unexpired ATs with zero network — an ASSUMED external
fact recorded only as a code comment (`:528-535`), not a tracked verification. Recovery does occur implicitly: the
next poll tick retries (only DEVICE_CA_BLOCKED short-circuits, `:503`). **Remediation:** add the MSAL cached-AT
semantics to the verification register (join V1); backoff optional.

### F-19 · LOW · `SILENT_REFRESH` unreachable; `apply_error` contract drift (B1)

`begin_silent_refresh` (`auth_state.py:185-189`) has zero production callers (grep: tests only), so the §6.4
SilentRefresh state a future "refreshing…" indicator needs is dead code; and `apply_error`'s docstring ("only called
while ACTIVE, SILENT_REFRESH, or INTERACTIVE_AUTH", `:194-196`) is already violated by its one real driver
(`auth_manager.py:547` calls it from whatever state holds, e.g. OFFLINE). Transitions from OFFLINE happen to do the
right thing today; a future guard enforcing the docstring would break OFFLINE recovery. **Remediation:** call
`begin_silent_refresh()` before the MSAL call, or amend the contract.

### F-20 · LOW · No user-presentable message field on error types (C3)

§9's messaging rules put raw codes in logs, never dialogs. The typed taxonomy is structurally sufficient for a
type→message map, but no type carries a `user_message`, and `InteractiveSignInFailedError.raw_error_description`
(`auth_manager.py:201-204`) is raw MSAL AADSTS text one attribute away from a dialog. Counter-examples in-repo prove
the pattern (`NATIVE_DISABLED_REASON`, `avd_bookmarks.py:56`). **Remediation:** plan the mapping table in the
UI-shell change explicitly, or rename to `raw_error_description_for_logs`. **Pinning test (UI change):** no dialog
string contains `AADSTS`.

### F-21 · LOW · Synchronous store I/O undocumented for future GTK callers (C2)

Every keyring/MSAL/network/subprocess call in the repo is disciplined through `run_blocking`, but
`StateStore.load()/save()` (with `fsync`, `state_store.py:305` — can stall on slow/network `$HOME`) and
`BookmarkStore.load()` (`avd_bookmarks.py:144`) are synchronous with no async wrapper and no docstring warning. The
UI-shell change will call these from GTK handlers and block the main loop (D-18, HIG responsiveness).
**Remediation:** docstring "call via `run_blocking` from the loop thread" now, or an async facade in the UI change.

### F-22 · LOW · Aggregated test gaps (D)

- `freerdp_probe`: no test asserts the recorded invocation is `[binary, "/version"]` with no `shell` kwarg — a
  regression to `shell=True` would pass the suite (`tests/test_freerdp_probe.py:38-41` records enough to assert it).
- Redaction: all tests use `winonlinux.*` loggers; the third-party requirement (msal/urllib3 DEBUG headers) is one
  `logging.getLogger("urllib3.connectionpool")` test away from pinned.
- `Retry-After: <HTTP-date>` never fed to `_parse_retry_after_seconds` in a test (code verified to fall back to
  backoff; unpinned).
- Loopback bind host/ephemeral port asserted implicitly only; cheap pin via `getsockname()`.
- Second-process no-side-effects (control 15) has only the manual procedure `tests/manual/app_uniqueness.md`; a
  headless test asserting `WinOnLinuxApplication.__init__` sets no stateful attributes is possible without a
  display.
- No test pins authority non-overridability, `_resolve_new_home_account_id`'s fallback, or
  `_warn_placeholder_client_id_once` firing (F-23).

### F-23 · INFO · Placeholder client-id (A4) — DECIDED-BUT-UNVERIFIED (D-19)

The one-time WARNING path is real (`auth_manager.py:105-122`, fires in `start()` on the zero GUID) but untested;

### F-24 · INFO · Bridge private APIs, no loop exception handler (B4)

`asyncio.events._set_running_loop` and `BaseEventLoop._run_once` (`asyncio_bridge.py:116,130`) are ASSUMED-stable
with no version-range record or CI matrix (see F-09 — 3.11 only). No `loop.set_exception_handler` anywhere;
unhandled task exceptions fall to asyncio's default handler at GC time. Today every app-level task catches its own
exceptions, so exposure is `_pump` raising into GLib if `_run_once` itself throws. Hardening: install a handler
logging through `logging_setup`; record the tested CPython range as a verification item.

### F-25 · INFO · Idle-pump cost (B4)

`_run_once()` blocks the shared thread in `select()` up to 20 ms per idle iteration and the 20 ms heartbeat
(`asyncio_bridge.py:77,83-91`) guarantees ~50 Hz wakeups. Deliberate and documented; recorded so V3's NFR
measurements know where to look for input latency or battery draw.

### F-26 · INFO · `load()` docstring wrong, behaviour right (B5)

`state_store.py:195-199` says "Never raises"; a missing migration step deliberately raises `KeyError`
(`:250-261`, pinned by `tests/test_state_store.py:117` — "raises instead of silently losing data"). Fix the
docstring. Migration's rewrite (`:240`) can also raise `OSError` on a full disk.

## 5. NOT findings — examined and correct (or correct-by-decision)

- **No plaintext cache fallback (D-2):** `fallback_to_plaintext=False` hardcoded; no parameter, env var, or
  exception handler reintroduces one; `ImportError` → `KeyringUnavailable`; probe failure → `False`, never a weaker
  store (`auth_cache.py:139-160`).
- **Health check isolated:** dedicated `_HEALTHCHECK_ITEM_NAME` distinct from the real cache item; the real cache's
  persistence object is never `save()`d by the health check (`auth_cache.py:104,163-182`).
- **`cache_write_serializer` covers every MSAL mutation path** — interactive exchange (`auth_manager.py:691-694`),
  silent acquisition (`:517-520`), `remove_account` (`:410-411`) — verified by enumerating all `self._app.*` sites.
- **Single-flight wraps acquire AND persist:** the per-(account, sorted-scopes) lock encloses the MSAL call whose
  internal persist sits inside the serializer — rotated-RT stranding closed.
- **Loopback:** binds `127.0.0.1:0`; state mismatch rejected *without* consuming the accept slot (tested); deadline
  measured from `start()` and untrickleable (tested); all three HTTP responses are fixed `text/plain` byte literals
  — no reflected query content, no XSS surface; auth code never logged.
- **Authority not overridable:** hardcoded `https://login.microsoftonline.com/{tenant}`, constructor-only tenant; no
  env or state-file read (`auth_manager.py:307`).
- **Claims passed verbatim, never logged** (`auth_state.py:73`, `auth_manager.py:650`); transition logs carry
  category names only; the claims test asserts boolean-style to avoid leaking the value into CI output.
- **Auth state machine (all transitions walked):** `invalid_grant` → REAUTH_REQUIRED isolated to one account; network
  error → OFFLINE never REAUTH_REQUIRED; user cancel restores prior state, and `SignInCancelled` is deliberately not
  an `AuthError` so broad catchers can't raise a dialog; cancel-then-notify ordering on account switch pinned; a
  cancelled `refresh_now` cannot write `last_result` (`CancelledError` is a `BaseException` past its except
  clauses). One taxonomy nuance, not a finding: `interaction_required` without claims classifies UNKNOWN →
  REAUTH_REQUIRED rather than §6.4's arrow to InteractiveAuth — behaviourally equivalent via the banner.
- **Graph client:** `Retry-After` integer honoured, absent/unparseable falls back to backoff without crashing
  (`graph_client.py:154-167`); backoff 1 s→30 s cap; `asyncio.sleep` only; 30 s timeout on the single request
  choke point every page passes through; `AuthError` aborts without burning retry budget; 404→`GraphNotFound`,
  403→`GraphConsentRequired`, `ProxyError`→`GraphProxyError` distinct from plain network error (§5.9 satisfied).
- **Paging/polling:** page-N failure fails the whole refresh, never a partial `Enumerated`; `Failed` never
  overwrites `last_result`; poll ticks strictly sequential (overrun delays, never overlaps); start/pause/resume/stop
  idempotent; poll task lives in the account's task group so switch-cancellation covers it.
- **Task registry:** executor failures propagate to the awaiter; done-callback discard cannot race group
  cancellation (copy-iterate + `discard`); destroy→recreate starts fresh.
- **Startup resilience:** probe and auth-start errors are attribute-stashed; tasks catch their own exceptions;
  `KeyringUnavailable` at startup leaves a usable signed-out app with the window presented — not a zombie (residual
  typing gap is F-13).
- **State store:** contrary to the audit prompt's premise, the file is effectively **0600** (`mkstemp` creates the
  temp 0600; `os.replace` preserves mode) and **fsync is present** before replace; rejection happens before any
  write; newer `schemaVersion` on disk left untouched with in-memory defaults; bare GUIDs persist (carve-out).
  Concurrent writers are safe **only** via single-instance enforcement — if FLAGS_NONE uniqueness is ever relaxed,
  the store needs its own lock. Directory-fsync is omitted: on power loss the rename itself may not be durable —
  explicitly acceptable for non-secret UI state and bookmarks.
- **Redaction mechanism:** LogRecord-factory enforcement covers third-party loggers (msal/urllib3) by construction;
  exc_info rendered-and-redacted eagerly then cleared, closing the traceback leak path; verbose (UPN-visible) mode
  is opt-in, unreachable by any CLI flag today, and persisted nowhere (grep of `StateStore` writes confirms). When a
  `--verbose` flag is added, the "documented as diagnostic" requirement must travel with it.
- **Subprocess/TLS hygiene:** zero `shell=True`, zero `verify=False`, zero `REQUESTS_CA_BUNDLE` tampering repo-wide;
  probe uses `shutil.which` + list argv + 5 s timeout; its loose version regex is not attacker-influenced today
  (local binary output) — correctly a non-finding.
- **Token hygiene in Graph path:** bearer held in a local and `del`eted post-request; log lines carry
  url/status/type/counters only (tested).
- **`avd_bookmarks`:** kind validated eagerly, malformed entries skipped-and-logged, and no launch/URL plumbing
  exists — no premature plumbing.
- **App identity:** `io.github.CalgaryMicrosoftUserGroup.WinOnLinux` is valid reverse-DNS for Flatpak/D-Bus (D-21);
  second launch presents the window via `_on_activate` (`app.py:153-165`). No hardcoded colors/CSS/StyleManager
  fights — libadwaita follows Yaru dark unopposed. `.desktop`/icon/AppStream absent — expected
  (`add-flatpak-packaging` unapplied), tracked gap, not a finding.
- **Accessibility/keyboard:** nothing to audit — the widget tree is a placeholder window with an empty `Gtk.Box`;
  assess in the UI-shell change.
- **Correct-by-decision, not reported:** no certificate pinning (D-4); keyring-required-no-fallback UX cost (D-2);
  UPN-in-fragment trade-off (§10.5); `trust_env` proxy inheritance (§5.9 — TLS remains end-to-end via CONNECT,
