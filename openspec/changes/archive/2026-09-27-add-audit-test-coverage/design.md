# Design: add-audit-test-coverage

## Context

This change is deliberately mostly-tests: the audited behaviors are already implemented and (except where other
audit changes fix them) correct — what is missing is the pin that keeps them true. The audit's controls matrix
(report §4) is the authoritative list of what is implemented-but-untested; this change works through it rather
than inventing coverage targets. It also owns the two infrastructure moves that make verification continuous: the
CI Python matrix and the dependency constraints file.

## Goals / Non-Goals

**Goals:**

- Every control in the audit matrix reads "implemented AND tested" or has a recorded reason it cannot (GTK/D-Bus
  behaviors stay manual per §13.4, but their automatable halves get headless tests).
- The dependency floor excludes known-CVE `requests` versions, and one generated constraints file feeds both CI
  and, later, the Flatpak manifest (D-3 alignment).
- CI failure — not an audit — is what catches the next 3.12/3.13 incompatibility.

**Non-Goals:**

- No new runtime behavior. Anything a test reveals as broken is fixed in the owning audit change
  (`fix-shutdown-loop-hygiene` for the known 3.12 failure), not silently here.
- No display-server or D-Bus-dependent CI (§13.4 stands); `tests/manual/app_uniqueness.md` remains the procedure
  for the Gio-forwarding half of control 15.
- No upper version bounds on libraries (floors + constraints, not caps — caps rot; the constraints file is the
  reproducibility mechanism).

## Decisions

- **Slowloris test uses real sockets with short timeouts,** like the existing loopback tests (they already open
  real TCP connections), overriding the 10 s read timeout via the module constant rather than monkeypatching
  asyncio — the test asserts the stalled connection is freed and a concurrent correct redirect lands within the
  deadline.
- **Second-process pin is a constructor-purity test:** instantiate `WinOnLinuxApplication` with GTK stubs (the
  repo's tests already stub PyGObject) and assert no cache/store/listener/task-registry attribute is constructed
  before `_first_activate`. This pins the half of control 15 that regression actually threatens; Gio's forwarding
  semantics stay a manual/ASSUMED item.
- **Constraints, not lockfile:** `constraints.txt` generated by `pip-compile` from `pyproject.toml`, consumed via
  `pip install -c`. Chosen over a full lock because the Flatpak manifest (D-3) wants a flat pinned module list,
  and constraints keep `pip install -e .` workflows intact for contributors. Refreshed deliberately; `pip-audit`
  in CI flags CVEs between refreshes. Recorded as a §14 decision (next free ID, D-23) with revisit trigger
  "Flatpak manifest generation adopts a tool that consumes a different pin format".
- **Matrix is {3.11, 3.12, 3.13} on `ubuntu-latest`,** all running the same unit suite; 3.11 remains the floor.
  The bridge's private-API assumption (`_run_once`, `_set_running_loop`) gains its tested-range record in the §12
  register pointing at the matrix.

## Risks

- `pip-audit`/matrix add CI time and a new flake surface; both are read-only jobs and can be non-blocking initially
  (report-only) with a task to promote them once quiet.
